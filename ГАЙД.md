# Jardin Rose — гайд по проекту

Учебное руководство к сайту салона флористики: какие языки использованы,
кто что делает, откуда берутся данные и как всё запустить.

Подходит как пояснительная записка к лабораторной или курсовой работе.

---

## 1. Что это за проект

Интернет-магазин цветочного салона в Алматы: каталог из 24 букетов,
конструктор собственного букета, корзина, промокоды, оформление
доставки и служебная страница со списком заказов.

Валюта — тенге (₸), язык — русский, оплата — карта, Kaspi QR, наличные.

---

## 2. Какие языки и технологии использованы

### Языки

| Язык | Где применяется | Файлы |
|---|---|---|
| **Python 3.13** | Сервер, база данных, вся деловая логика, генератор графики | `app.py`, `engine/*.py` |
| **JavaScript (ES2020)** | Поведение страницы в браузере: каталог, корзина, анимации | `static/js/*.js` |
| **HTML5** | Разметка витрины | `vikanastya.html` |
| **CSS3** | Оформление, анимации, мобильная вёрстка | `style.css`, `static/css/*.css` |
| **SQL (диалект SQLite)** | Запросы к базе: выборки, фильтры, вставка заказов | внутри `engine/*.py` |

**C++ в проекте не используется** — для веб-приложения он не нужен.
Задачи, где он был бы уместен (тяжёлые вычисления, обработка видео),
здесь не возникают, а обработку изображений берёт на себя Pillow —
библиотека, у которой ядро как раз написано на C.

### Библиотеки Python

| Библиотека | Зачем |
|---|---|
| **Flask 3.1** | Веб-сервер: принимает запросы браузера, отдаёт страницы и JSON |
| **Pillow 12** | Генерация графики: спрайты лепестков, паттерн, запасные картинки букетов |
| **truststore** | Чтобы загрузка фотографий работала при антивирусе с проверкой HTTPS |
| **sqlite3** | Встроена в Python. База данных в одном файле, сервер БД не нужен |
| **Playwright** | Автотесты в настоящем браузере (использовался при разработке) |

### Что применяется без библиотек

* `fetch` и `AbortController` — запросы к серверу и их прерывание по таймауту;
* `IntersectionObserver` — появление секций при прокрутке;
* `Canvas 2D` — анимация падающих лепестков;
* `localStorage` — корзина в режиме без сервера;
* CSS Grid и Flexbox — вся сетка;
* CSS Custom Properties (переменные) — фирменная палитра в одном месте.

## 4. Как это работает: путь одного клика

Разберём, что происходит, когда посетитель нажимает «В корзину».

```
1. БРАУЗЕР
   main.js ловит клик по кнопке .btn-add-cart
   и отправляет запрос:  POST /api/cart/add  { "product_id": 5 }

2. СЕРВЕР — app.py
   Маршрут api_cart_add() принимает запрос,
   безопасно превращает product_id в число,
   проверяет, что такой букет есть в базе.

3. ДВИЖОК — engine/cart.py
   add_product() кладёт в сессию только id и количество.
   ЦЕНУ ИЗ БРАУЗЕРА НЕ БЕРЁТ.

4. ДВИЖОК — engine/cart.py → build_state()
   Читает актуальные цены из таблицы products,
   считает сумму, скидку по промокоду, стоимость доставки.

5. СЕРВЕР
   Возвращает готовое состояние корзины в формате JSON.

6. БРАУЗЕР
   main.js перерисовывает корзину, обновляет счётчик
   в шапке и показывает всплывающее уведомление.
```

**Главный принцип:** браузер сообщает, ЧТО и СКОЛЬКО. Сколько это
стоит — решает только сервер. Иначе достаточно открыть инструменты
разработчика, чтобы купить букет за один тенге.

## 5. Откуда берутся данные

| Что | Источник | Кто читает |
|---|---|---|
| Каталог букетов | таблица `products` в `data/jardin.db` | `engine/catalog.py` |
| Первичное наполнение | список `PRODUCTS_SEED` в `engine/db.py` | один раз при первом запуске |
| Фотографии букетов | Unsplash → `static/img/bouquets/` | скачивает `engine/photos.py` |
| Цены конструктора | таблица `builder_options` | `engine/cart.py` |
| Промокоды | таблица `promo_codes` | `engine/cart.py` |
| Правила доставки | `engine/config.py` | `engine/cart.py` |
| Заказы | таблицы `orders` и `order_items` | `engine/orders.py` |
| Корзина посетителя | подписанная cookie-сессия Flask | `engine/cart.py` |

## 6. Два режима работы

Сайт открывается двумя способами, и он сам понимает, в каком режиме работает.

### Режим движка (полноценный магазин)

```
python app.py
```
Затем `http://127.0.0.1:5000`. Данные идут с сервера, корзина и заказы
хранятся в базе, цены считает Python. Заказы видны на `/admin`.

### Режим без сервера (только витрина)

Двойной клик по `vikanastya.html`. Браузер запрещает такой странице
делать сетевые запросы, поэтому каталог берётся из заранее выгруженного
файла `static/js/catalog-data.js`, а корзина живёт в `localStorage`.
Заказ при этом никуда не отправляется — показывается демонстрационный номер.

Переключение делает объект `backend` в `static/js/main.js`.

## 6.1. Открыть на смартфоне

Есть два способа, оба работают.

### Способ А — по Wi-Fi с компьютера (проще)

1. Запустить `ЗАПУСК.bat` на компьютере.
2. В окне сервера будет строка вида
   `С ТЕЛЕФОНА: http://192.168.0.15:5000` — это адрес компьютера
   в домашней сети.
3. Подключить телефон к **тому же Wi-Fi** и открыть этот адрес в браузере.

Если не открывается — Windows блокирует входящие подключения.
При первом запуске появится окно брандмауэра: нужно нажать
«Разрешить доступ» для частных сетей.

Сервер слушает `0.0.0.0` — то есть принимает запросы от других
устройств сети, а не только от самого компьютера.

### Способ Б — скопировать папку на телефон

Скопировать всю папку проекта на телефон (кабелем, через облако или
мессенджер) и открыть `vikanastya.html` любым браузером. Сайт работает
без сервера и без интернета: витрина, поиск, фильтры, конструктор и
корзина. Заказ при этом не отправляется — показывается демонстрационный
номер.

Размер папки без макета `проект.psd` — около 19 МБ.

### Установка на домашний экран

Открыв сайт на телефоне, в меню браузера выбрать «Установить приложение»
(Android) или «На экран Домой» (iPhone). Появится значок с розой, и
сайт будет открываться без адресной строки, как обычное приложение.
За это отвечает `static/manifest.webmanifest`.

## 6.2. Работа без интернета

Сайт полностью автономен: **ни одного обращения к чужим серверам**.

Изначально страница тянула шрифты с `fonts.googleapis.com`, иконки с
`cdnjs.cloudflare.com`, а фотографии отзывов с `unsplash.com`. Без сети
заголовки теряли шрифт, вместо иконок появлялись пустые квадраты,
аватары исчезали.

Теперь всё лежит внутри проекта:

| Что | Где | Размер |
|---|---|---|
| Шрифты (17 файлов woff2) | `static/fonts/` | 0,45 МБ |
| Иконки Font Awesome | `static/vendor/fontawesome/` | 0,29 МБ |
| Фотографии букетов | `static/img/bouquets/` | 12,8 МБ |
| Фотографии конструктора | `static/img/builder/` | 0,31 МБ |
| Аватары отзывов | `static/img/reviews/` | 0,02 МБ |

Скачивает всё это `engine/assets.py` и `engine/photos.py` — один раз
при первом запуске. Проверить готовность:

```powershell
python -m engine.assets
```

Последняя строка ответа скажет: «Готовность к работе без интернета: да».

Проверено автоматическим тестом: при полностью заблокированной сети
сайт открывается со всеми шрифтами, иконками и фотографиями,
ноль внешних запросов, ноль ошибок.

## 7. Запуск с нуля

```powershell
# 1. Установить библиотеки
python -m pip install -r requirements.txt

# 2. Запустить движок
python app.py
```

При первом запуске автоматически произойдёт:
1. создание базы `data/jardin.db` и наполнение каталогом;
2. загрузка фотографий букетов (если их ещё нет);
3. генерация спрайтов лепестков и фавиконки;
4. выгрузка каталога в `static/js/catalog-data.js`.

Полезные команды по отдельности:

```powershell
python -m engine.db          # пересоздать базу
python -m engine.photos      # докачать фотографии
python -m engine.export      # обновить данные для офлайн-режима
python -c "import sys;sys.path.insert(0,'.');from engine.graphics import generate_all;generate_all(force=True)"
```

## 8. Адреса API

| Адрес | Метод | Что делает |
|---|---|---|
| `/` | GET | Витрина (vikanastya.html) |
| `/admin` | GET | Список заказов для флориста |
| `/api/settings` | GET | Валюта, контакты, поводы, дополнения |
| `/api/catalog` | GET | Каталог с фильтрами |
| `/api/product/<id>` | GET | Один букет |
| `/api/occasions` | GET | Поводы для покупки |
| `/api/addons` | GET | Дополнения к букету |
| `/api/builder` | GET | Составляющие конструктора |
| `/api/builder/price` | POST | Расчёт цены авторского букета |
| `/api/cart` | GET | Состояние корзины |
| `/api/cart/add` | POST | Добавить букет |
| `/api/cart/add-custom` | POST | Добавить букет из конструктора |
| `/api/cart/qty` | POST | Изменить количество |
| `/api/cart/remove` | POST | Убрать позицию |
| `/api/cart/promo` | POST | Применить промокод |
| `/api/cart/addon` | POST | Добавить или убрать дополнение |
| `/api/wishlist/toggle` | POST | Избранное |
| `/api/order` | POST | Оформить заказ |
| `/api/subscribe` | POST | Подписка на рассылку |

Фильтры каталога: `category`, `q`, `min_price`, `max_price`,
`in_stock`, `discount`, `occasion`, `sort`.

## 9. Структура базы данных

```
products          букеты: цена, категория, поводы, рейтинг, состав
builder_options   составляющие конструктора: цветы, зелень, упаковка
addons            дополнения: ваза, шоколад, открытка, шар
promo_codes       промокоды: процент или сумма скидки, минимум заказа
orders            заказы: получатель, адрес, дата, суммы, статус
order_items       состав заказа (снимок цен на момент покупки)
subscribers       подписчики рассылки
```

Связь: `order_items.order_id → orders.id` (внешний ключ с каскадным
удалением). Остальные таблицы независимы.

## 10. Приёмы, на которые стоит обратить внимание

Каждый разобран комментарием прямо в коде — здесь только список,
где искать.

| Приём | Файл |
|---|---|
| Параметризованные SQL-запросы (защита от инъекций) | `engine/catalog.py` |
| Белый список сортировок вместо подстановки текста в SQL | `engine/catalog.py` |
| Цены только из базы, никогда из браузера | `engine/cart.py` |
| Проверка формы на сервере, а не только в браузере | `engine/orders.py` |
| Транзакция `BEGIN IMMEDIATE` против гонки номеров заказов | `engine/orders.py` |
| Режим WAL в SQLite для одновременных посетителей | `engine/db.py` |
| Экранирование данных пользователя в HTML (защита от XSS) | `app.py`, `static/js/main.js` |
| Один обработчик событий на всю сетку вместо сотни кнопок | `static/js/main.js` |
| Повтор запроса при обрыве связи и таймаут через AbortController | `static/js/main.js` |
| Сторож, который поднимает страницу после сбоя скрипта | `static/js/main.js` |
| `IntersectionObserver` и ловушка с порогом на длинных секциях | `static/js/main.js` |
| Анимация только `transform` и `opacity` | `static/css/animations.css` |
| Поддержка «уменьшить движение» для доступности | `static/css/animations.css` |
| Безопасные зоны экрана iPhone (`env(safe-area-inset-*)`) | `static/css/mobile.css` |
| Поле ввода 16px, чтобы Safari не увеличивал страницу | `static/css/mobile.css` |
| Кэш и математика поворота при отрисовке лепестка | `engine/graphics.py` |

## 11. Что можно доделать

Идеи для развития, если работа продолжится:

1. **Личный кабинет** — история заказов, повтор заказа в один клик.
2. **Подписка на цветы** — регулярная доставка раз в неделю или месяц.
3. **Настоящая оплата** — приём Kaspi и банковских карт.
4. **Отзывы с фотографиями** от покупателей, с проверкой покупки.
5. **Панель флориста** — смена статуса заказа, печать бланка доставки.
6. **Уведомления** в WhatsApp или Telegram о статусе доставки.
7. **Развёртывание на хостинге** — сервер `gunicorn`/`waitress` вместо
   встроенного, база PostgreSQL вместо SQLite при росте нагрузки.
